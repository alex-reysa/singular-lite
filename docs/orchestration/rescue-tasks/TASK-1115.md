   attempt/session, candidate/worktree revision, requested and effective model,

   campaign and immutable bundle identity. Preserve unknown identity fields
   explicitly; refuse strict admission when a required binding is unavailable.
   Extend both schema copies consistently and define compatibility for retained
   bundles. Do not rewrite historical bundles or weaken schema validation.

3. Account separately for mandatory task/policy obligations, required review
   evidence, selected code/documents/approved memory, supported visible
   history/tool/skill content, and output reserve. Distinguish exact
   host-managed bytes, provider-observable quantities and unknown components.
   Specify units, estimator/tokenizer identity, coverage and overlap rules.
   Never subtract token reserves from byte limits without a declared supported
   conversion; missing usage/history is unknown, never zero. Cumulative input
   and cached-input usage are not instantaneous occupancy or money.

4. Enforce managed admission before provider launch using the final composed
   bytes and every applicable existing cap. Mandatory content plus required
   reserve that cannot fit fails explicitly before invocation. Retain the full
   task contract and open/violated obligations across planner, first-worker,
   retry and auditor assembly; a task-path reminder is insufficient.

5. Admit optional content deterministically into the remaining allowance.
   Record selection order, truncation/omission reasons, source ranges and
   hashes matching delivered bytes. Optional overflow alone must not be
   mislabeled mandatory overflow. Preserve required evidence completeness and
   existing tamper, campaign and policy checks. Repeated delivery remains
   charged according to the existing durable ledger; deduplication must not
   erase real delivery charges.

6. Apply aggregate admission to repeated host-mediated retrieval and resume
   deltas at supported interception points. Reserve allowance before releasing
   a response so concurrent reads cannot overspend. Reauthorize each delivery,
   retain restart-safe accounting, and test exhaustion across repeated reads,
   retries and resumes. Direct read-only context search/get/explain remains
   free of cache, lock, ledger and reviewed-memory writes; accounting belongs
   to the host invocation boundary.

   effective configuration: initial prompt control, host-broker retrieval,

   calls or browser probes. Unavailable controls remain unverified.

   retrieval or provider history bypass supported interception, identify that

   A configured output reserve is not proof of a provider-enforced output cap.
   Do not claim universal provider context occupancy, history deletion or
